# 1. 文档说明

## 1.1 编写目的

本文档用于明确肺炎 X 光片智能辅助筛查系统的产品定位、业务边界、用户角色、功能需求、交互规则、接口约定、非功能性要求、UI/UX 规范与测试验收标准，作为后续系统设计、开发联调、测试验收和答辩材料的统一依据。

本文档重点回答以下问题：

1. 系统必须做什么、明确不做什么；
2. 医生用户如何完成一次完整的辅助筛查；
3. 每个功能模块包含哪些字段、交互和边界条件；
4. 前后端需要约定哪些核心数据；
5. 系统在性能、安全、兼容性和测试方面达到什么标准；
6. 最终页面需要呈现怎样的医疗科技视觉与动效体验。

## 1.2 项目背景与已确定事实

算法实验和数据评估已经完成，系统建设应严格遵循以下已冻结事实，不得在需求、界面文案或答辩材料中夸大或改写。

| 项目事实 | 已确定内容 |
|---|---|
| 最终在线模型 | `resnet50_baseline`，无 SE/CBAM 注意力模块 |
| 部署格式 | FP32 ONNX |
| 模型输入 | `[B, 3, 224, 224]`，灰度图转三通道并按 ImageNet 均值和标准差归一化 |
| 模型输出 | `logits`，两个类别，固定顺序为 `NORMAL`、`PNEUMONIA` |
| 概率计算 | 对 `logits` 执行 Softmax，得到两类概率 `probs` |
| 肺炎判定阈值 | `0.5101`，当 `probs.PNEUMONIA >= 0.5101` 时判为 `PNEUMONIA` |
| 测试集指标 | Accuracy `0.9743`、AUC `0.9946`、PNEUMONIA Recall `0.9812`、F1(macro) `0.9675` |
| 可解释性 | 调用 Grad-CAM 生成热力图及原图叠加图 |
| ONNX 本机性能 | FP32 模型 CPU 单张平均推理约 `28.3 ms`，该数据仅作为实验环境参考，不作为生产 SLA |

> **重要说明：** 项目名称保留“基于注意力机制增强 CNN”，但 E2 注意力消融实验的结论是 SE/CBAM 均未超过无注意力基线。因此，在线系统必须如实标注使用 `resnet50_baseline`，并在模型信息看板中展示注意力消融的负结果及完整诊断链。课程名称与在线模型事实不得混淆。

# 2. 系统定位与边界（红线）

## 2.1 产品定位

本系统是面向医生的**肺炎 X 光片智能辅助筛查参考工具**，仅完成单张胸部 X 光片的二分类辅助判断，并以 Grad-CAM 热力图展示模型关注区域，帮助医生快速初筛和交叉参考。

系统输出不是诊断结论，不提供治疗方案，不替代医生阅片，不进入临床诊疗闭环。

## 2.2 强制免责声明

以下免责声明必须在登录页页脚、诊断结果卡片、历史详情弹窗和报告导出图片中持续可见。不得以折叠、极小字号或仅通过悬浮提示的方式隐藏。

> **免责声明：** 本系统为肺炎 X 光片智能辅助筛查参考工具，仅输出 NORMAL / PNEUMONIA 二分类概率及可视化参考，不构成临床诊断、治疗建议或医疗决策依据。系统结果不得替代执业医师结合病史、体征、实验室检查及影像学表现作出的综合判断。

结果卡片中建议同时使用醒目的信息提示图标和以下短文案：

> AI 结果仅供辅助筛查参考，最终诊断请以执业医师综合判断为准。

## 2.3 系统范围内与范围外

| 分类 | 内容 | 处理要求 |
|---|---|---|
| 范围内 | 医生登录与 JWT 鉴权 | 支持预置演示账号，不开放自主注册 |
| 范围内 | 单张 JPG/PNG 胸片上传 | 支持拖拽与文件选择 |
| 范围内 | `NORMAL / PNEUMONIA` 二分类 | 输出概率、类别和固定阈值 |
| 范围内 | Grad-CAM 原图与热力图对比 | 热力图仅作模型关注区域参考 |
| 范围内 | 保存、筛选、查看和删除诊断记录 | 记录归属当前登录医生 |
| 范围内 | 阴阳性比例和近 7 天诊断趋势 | 基于已保存记录统计 |
| 范围内 | 模型架构、指标与实验结论展示 | 静态看板，内容与实验报告一致 |
| 范围内 | 结果卡片导出为 PNG | 可选功能 |

## 2.4 不可突破的产品红线

1. **辅助定位红线：** 所有结果页必须明确显示免责声明，禁止使用“确诊”“自动诊断”“替代医生”等表述。
2. **分类范围红线：** 仅支持 `NORMAL / PNEUMONIA` 二分类，禁止出现多分类标签或未经验证的疾病名称。
3. **影像格式红线：** 不解析 DICOM，不支持 DICOM 文件上传；系统只接受 `.jpg`、`.jpeg`、`.png` 图像。
4. **患者管理红线：** 不建设患者主索引、病历、随访或处方模块，不采集姓名、身份证号、住院号、手机号等个人身份信息。
5. **模型事实红线：** 在线模型必须标注为 `resnet50_baseline`，不得宣称为 SE/CBAM 增强版。
6. **可解释性红线：** Grad-CAM 只能描述为“模型关注区域”，不得描述为“病灶边界”或“确诊依据”。
7. **数据安全红线：** 密码不得写入日志、URL、前端源码或 `localStorage`；上传文件不得直接以原文件名落盘或执行。
8. **决策红线：** 前端不得自行重算分类结果；必须展示后端返回的 `label`、`probs` 和 `threshold`，避免版本漂移造成判定不一致。

## 2.5 命名与事实一致性要求

- 课程项目名称可以继续使用“基于注意力机制增强 CNN 的肺炎 X 光片智能辅助诊断系统”。
- 工作台、历史详情、报告导出和模型信息看板必须显示在线模型版本 `resnet50_baseline`。
- 模型信息页必须设置“注意力消融实验”区块，明确说明：SE/CBAM 未超过基线，最终采用无注意力基线。
- 答辩材料不得将实验探索过程包装成在线功能已使用注意力模块；应将“负结果分析完整、决策可追溯”作为项目严谨性的加分点。

# 3. 用户角色与核心场景

## 3.1 用户角色定义

系统仅设置一个业务角色：**医生（DOCTOR）**。

| 角色 | 角色说明 | 可访问功能 | 数据权限 |
|---|---|---|---|
| 医生 | 使用系统进行 X 光片辅助筛查的执业医师或课程演示用户 | 登录、诊断工作台、历史记录、统计仪表盘、模型信息看板、报告导出 | 仅查看和操作本人创建的诊断记录 |

系统不设置管理员后台、患者端、科研端或对外开放注册。演示账号由部署配置或初始化流程预置，密码以哈希形式保存，不得硬编码在前端代码和公开文档中。

## 3.2 访问控制原则

- 未登录用户只能访问登录页。
- 所有业务页面的后端请求必须携带有效 JWT。
- 前端路由守卫负责页面级拦截，后端接口鉴权负责最终安全校验，二者缺一不可。
- 医生只能访问本人记录；直接访问他人记录 ID 时必须返回 `403` 或 `404`。
- 角色非法、Token 无效或 Token 过期时，统一返回未授权状态并引导重新登录。

## 3.3 页面与路由建议

| 页面 | 建议路由 | 是否需要登录 | 主要用途 |
|---|---|---|---|
| 登录页 | `/login` | 否 | 账号密码登录 |
| 诊断工作台 | `/workspace` | 是 | 上传、分析、结果查看、保存 |
| 历史记录 | `/history` | 是 | 分页、筛选、详情、删除 |
| 统计仪表盘 | `/dashboard` | 是 | 饼图与近 7 天趋势 |
| 模型信息看板 | `/model-info` | 是 | 展示模型、指标与实验结论 |
| 404 页面 | 任意未知路由 | 视情况 | 返回工作台或登录页 |

## 3.4 核心用户旅程

| 步骤 | 用户操作 | 系统反馈 | 异常与边界 |
|---|---|---|---|
| 1. 登录 | 输入账号和密码，点击“登录” | 校验成功后签发 JWT，进入诊断工作台；展示医生名称和免责声明 | 账号或密码错误时显示统一提示；Token 过期时回到登录页并保留安全的回跳地址 |
| 2. 上传 X 光片 | 拖拽或选择单张 JPG/PNG 文件 | 显示文件预览、文件名、大小和“开始分析”按钮 | 非图片、伪装图片、超过 10 MB、损坏图片均在上传阶段或分析前拦截 |
| 3. 等待分析 | 点击“开始分析” | 图片区域显示 X 光扫描线动画和“AI 正在分析影像特征”状态 | 分析期间禁用重复提交；网络超时、模型不可用或 Grad-CAM 失败时给出明确错误或降级结果 |
| 4. 查看结果 | 查看分类徽章、置信度、肺炎概率、阈值提示、原图与 Grad-CAM | 红色或绿色结果徽章、数字滚动递增、左右影像对比、免责声明 | 标签颜色不得作为唯一信息；热力图失败时仍显示分类结果并提示可视化不可用 |
| 5. 保存记录 | 点击“保存记录” | 记录写入历史，提示保存成功，按钮变为已保存 | 保存失败时保留当前结果并允许重试；重复点击不得生成重复记录 |
| 6. 查看历史 | 进入历史记录页，筛选或打开详情 | 显示分页列表；详情弹窗复用只读结果卡片 | 无记录时展示空状态；记录不存在或无权访问时提示并刷新列表 |

### 4.3.2 JWT 登录与鉴权逻辑

1. 前端提交账号和密码；密码只允许出现在 HTTPS 请求体中，不得放入 URL。
2. 后端校验账号状态和密码哈希，成功后签发短期 JWT，建议有效期 2 小时。
3. JWT 载荷只包含用户 ID、角色、签发时间、过期时间和令牌 ID，不包含密码、影像或其他敏感信息。
4. 前端将 Token 保存在 `sessionStorage` 和服务运行内存中，不写入 `localStorage`；关闭浏览器会话后失效。
5. 所有受保护接口使用 `Authorization: Bearer <JWT>` 请求头。
6. 路由守卫在进入业务路由前检查 Token 是否存在、格式是否有效、客户端记录的过期时间是否已到；最终有效性以后端校验为准。
7. 后端拒绝无效、篡改、过期或已注销的 Token。
8. 系统只提供登录和退出，不提供注册、找回密码和修改角色功能。

### 4.3.3 Token 过期处理

| 场景 | 前端行为 | 后端行为 |
|---|---|---|
| 请求前发现 Token 已过期 | 清理会话，跳转 `/login?redirect=<原安全路径>` | — |
| 请求返回 `401 TOKEN_EXPIRED` | 只弹一次“登录已过期，请重新登录”，清理会话并跳转登录页 | 返回统一未授权错误结构 |
| 请求返回 `401 INVALID_TOKEN` | 清理会话并跳转登录页 | 不返回具体安全细节 |
| 多个请求同时返回 401 | 使用单一跳转锁，避免重复弹窗和重复跳转 | — |
| 登录成功且存在合法回跳地址 | 跳转原业务页面 | 校验回跳路径必须是站内白名单路径，防止开放重定向 |
| 用户主动退出 | 清理 Token 与页面缓存，跳转登录页 | 可选将 Token 加入短期黑名单；课程演示环境可只做客户端清理 |

### 4.3.4 边界条件

- 空账号、空密码或格式不合法时，前端行内提示，不发起请求。
- 账号或密码错误时，不透露具体哪一项错误。
- 连续登录失败达到 5 次时，建议锁定 5 分钟并返回通用提示；锁定策略不得导致演示账号永久不可用。
- 页面刷新后，若会话仍有效则保持登录；若 Token 已失效，必须重新登录。
- 前端路由隐藏不等于安全控制，任何历史记录、统计和预测接口都必须由后端再次鉴权。
- 密码输入框不得被浏览器自动填充脚本写入日志，登录表单不得埋点采集输入值。
## 4.4 M2 诊断工作台（核心）

### 4.4.1 页面结构

诊断工作台采用单页分阶段交互，建议从上到下划分为：

1. 页面标题区：显示“肺炎 X 光片智能辅助筛查”“仅支持 NORMAL / PNEUMONIA 二分类”和在线模型版本。
2. 上传卡片区：拖拽上传、文件要求、预览与开始分析操作。
3. AI 分析状态区：扫描线动画、当前处理阶段和不提供虚假百分比的状态提示。
4. 结果卡片区：分类徽章、置信度、肺炎概率、阈值提示、影像对比、模型信息和免责声明。
5. 操作区：保存记录、重新分析、导出图片。

在 1920×1080 分辨率下，结果卡片的原图与 Grad-CAM 应优先左右并排展示；在较窄视口下允许上下堆叠，但不得压缩到不可辨识。

### 4.4.2 上传区字段与交互

| 拖拽上传区 | 拖放区域 | — | 接受单张 `.jpg`、`.jpeg`、`.png` | 拖入文件时高亮边框；拖出后恢复 |
| 文件选择入口 | 按钮/链接 | — | 文件选择器限制为 JPG/PNG | 键盘可聚焦、可操作 |
| 文件预览 | 图像缩略图 | — | 保持原始宽高比 | 选中后立即本地预览，不上传原图 |
| 文件名 | 只读文本 | — | 超长名称省略显示，悬浮可看全名 | 文件名不参与后端落盘路径 |
| 文件大小 | 只读文本 | — | 统一显示 MB，保留两位小数 | 超过 10 MB 时标红并禁止分析 |
| 移除按钮 | 次级按钮 | — | 清空当前文件与预览 | 分析中不可移除 |

### 4.4.3 上传校验规则

| 校验层级 | 规则 | 失败处理 |
|---|---|---|
| 文件数量 | 每次仅允许 1 个文件 | 多文件拖入时提示“每次仅支持分析 1 张影像” |
| 扩展名 | P0 允许 `.jpg`、`.png`；`.jpeg` 作为 JPG 兼容别名 | 其他扩展名直接拒绝 |
| MIME 类型 | 仅允许 `image/jpeg`、`image/png` | MIME 不匹配时拒绝 |
| 文件大小 | `0 < size <= 10 MB` | 空文件拒绝；恰好 10 MB 允许；大于 10 MB 拒绝 |
| 文件内容 | 后端读取文件头并实际解码图像 | 扩展名与内容不一致、损坏、无法解码时拒绝 |
| 图像尺寸 | 最小 `64×64`；建议最大不超过 40 MP | 过小或像素总量过大时拒绝，防止异常图片耗尽资源 |
| 色彩模式 | 灰度、RGB、RGBA 均可读取 | 后端统一转换为 RGB；Alpha 通道不作为有效医学信息 |
| 特殊格式 | SVG、GIF、BMP、WebP、DICOM、压缩包、可执行文件 | 一律拒绝，不尝试解析 |
| 文件安全 | 使用随机文件名落盘；禁止路径拼接用户文件名 | 防止路径穿越和覆盖已有文件 |
| 元数据 | 保存前移除不必要的 EXIF 等元数据 | 降低无意携带设备信息或隐私信息的风险 |

前端校验用于即时反馈，后端校验用于最终安全控制。任何仅依赖前端 `accept` 属性或扩展名判断的实现均视为不合格。

| 状态 | 页面表现 | 允许操作 | 禁止操作 |

| 上传/分析中 | 图片上覆盖扫描线，显示“AI 正在分析影像特征” | 查看当前状态 | 重复提交、移除文件、切换当前影像 |
| 分析成功 | 展示完整结果卡片和操作按钮 | 保存、导出、重新分析 | 重复分析同一请求 |

### 4.4.5 X 光扫描线分析动效

扫描动效是 P0 交互要求，必须由 CSS 动画实现，不依赖 GIF、视频或外部动画库。

| 设计项 | 要求 |
|---|---|
| 动画载体 | 在已选影像上方叠加半透明深色遮罩，扫描线限制在图像边界内 |
| 扫描线样式 | 约 2 px 高的极光青色水平线，带柔和发光和渐变拖尾，颜色使用 `#06B6D4` |
| 运动方式 | 从图像顶部匀速扫描到底部，单周期约 1.8 秒，循环播放 |
| 辅助元素 | 可叠加低透明度网格、十字准星或四角取景框，但不得遮挡影像主体 |
| 状态文案 | 显示“AI 正在分析影像特征，请稍候”，不显示虚假的 37%、82% 等进度 |
| 阶段提示 | 可按顺序显示“影像预处理”“模型推理”“生成 Grad-CAM”；仅作状态说明，不作为精确进度 |
| 最短展示 | 为避免动画一闪而过，建议至少保持 900 ms 可见；不得为了动画人为等待超过 2 秒 |
| 结束过渡 | 收到结果后扫描线淡出，结果卡片以 300 ms 淡入和轻微上移出现 |
| 失败处理 | 扫描线立即停止，遮罩切换为错误状态，不得继续循环动画 |
| 无障碍 | 用户启用“减少动态效果”时，用静态扫描框和状态文字替代循环扫描线 |

分析过程中不得展示“诊断完成”或“确诊”等措辞；完成后统一使用“AI 辅助筛查结果”。

### 4.4.6 结果展示字段

| 结果字段 | 展示要求 |
|---|---|
| 分类徽章 | `PNEUMONIA` 使用红色系并配警告图标；`NORMAL` 使用绿色系并配通过图标；必须同时显示文字，不得仅靠颜色区分 |
| 主置信度 | 展示判定类别的概率百分比，保留两位小数，并带数字滚动递增动画 |
| 肺炎概率 | 单独展示 `probs.PNEUMONIA` 的百分比，便于医生理解阈值关系 |
| 判定阈值 | 显示“判定阈值 0.5101（肺炎概率 ≥ 0.5101 时判为 PNEUMONIA）” |
| 判定规则提示 | 用一句话说明当前结果与阈值的关系，例如“肺炎概率 57.88%，高于阈值 0.5101” |
| 原始影像 | 标注“原始 X 光片”，保持原始宽高比 |
| Grad-CAM | 标注“Grad-CAM 模型关注区域”，并提示“高亮不代表病灶边界” |
| 模型版本 | 显示 `resnet50_baseline` 和部署格式 `FP32 ONNX` |
| 推理时间 | 显示后端返回的 `inference_ms`，单位毫秒；仅作参考 |
| 生成时间 | 显示当前时区时间，精确到秒 |
| 免责声明 | 在结果卡底部常驻，不得折叠 |

### 4.4.7 分类判定与置信度口径

1. 设 `p = probs.PNEUMONIA`。
2. 当 `p >= threshold` 时，判定为 `PNEUMONIA`；否则判定为 `NORMAL`。
3. `threshold` 默认且当前固定为 `0.5101`，但前端必须以接口返回值为准，不得在多个页面分别硬编码。
4. 主置信度定义为判定类别的概率：肺炎时显示 `probs.PNEUMONIA`，正常时显示 `probs.NORMAL`。
5. 页面同时显示肺炎概率和判定阈值，避免医生误以为主置信度始终代表肺炎概率。
6. 百分比默认保留两位小数；阈值默认显示四位小数，并可附加 `51.01%` 的换算提示。
7. 若后端返回的 `label` 与 `probs`、`threshold` 按上述规则计算出的结果不一致，前端应显示“结果数据异常，请重新分析”，不得保存该记录。
8. 数字滚动动画只负责视觉呈现，动画结束值必须与接口原值一致，不得四舍五入后再参与判定。

### 4.4.8 原图与 Grad-CAM 对比展示

| 展示项 | 要求 |
|---|---|
| 布局 | 左侧原始影像，右侧 Grad-CAM 叠加图；两图同高、同宽、同比例对齐 |
| 默认视图 | 右侧默认展示原图与 Jet 热力图的叠加效果 |
| 可选视图 | P1 支持在“叠加图”和“纯热力图”之间切换 |
| 色彩说明 | 展示低关注度到高关注度的渐变色条，并说明颜色越暖表示模型关注度越高 |
| 对齐说明 | 两图必须基于同一张已预处理但保持原始视觉比例的影像，不得产生明显裁切错位 |
| 加载状态 | Grad-CAM 未生成时展示骨架屏或“热力图生成中” |
| 失败降级 | 分类结果仍可展示；右侧显示“热力图暂不可用”，并允许重新生成或重新分析 |
| 解释边界 | 必须显示“高亮区域反映模型关注区域，不代表病灶边界或临床诊断依据” |

### 4.4.9 保存记录

- 结果生成后不自动进入历史；医生点击“保存记录”后才计入历史列表和统计。
- 保存请求使用 `prediction_id` 关联当前临时预测结果，不重复上传影像。
- 首次保存成功时按钮显示“已保存”；同一 `prediction_id` 重复提交应保持幂等，不生成重复记录。
- 保存内容包括影像及其 Grad-CAM 结果、预测标签、两类概率、阈值、模型版本、推理时间和创建时间。
- 不保存患者姓名、身份证号、住院号等身份信息。
- 保存失败时结果卡片必须保留，显示可重试提示，不得要求医生重新上传或重新分析。
- 未保存结果只作为临时会话数据；页面刷新或离开前应提示“当前结果尚未保存”。

### 4.4.10 边界条件

| 场景 | 预期处理 |
|---|---|
| 未选择文件即点击分析 | 按钮不可用；若通过异常方式触发，提示“请先选择影像” |
| 上传非图片格式 | 前端即时拒绝；后端仍返回 `400 INVALID_FILE_TYPE` |
| 将文本或程序文件改名为 `.jpg` | 后端文件头或解码校验失败，返回 `400 INVALID_FILE_CONTENT` |
| 上传空文件 | 拒绝并提示“文件为空或已损坏” |
| 文件恰好 10 MB | 允许上传和分析 |
| 文件大于 10 MB | 拒绝并提示“文件大小不得超过 10 MB” |
| 上传 DICOM | 明确提示“系统不支持 DICOM，请上传 JPG/PNG” |
| 上传损坏或截断图片 | 提示“影像无法解析，请更换文件” |
| 拖入多张图片 | 不选择任何文件或仅保留提示，不进入分析 |
| 分析中再次点击 | 按钮禁用，不产生第二个请求 |
| 分析中 Token 过期 | 停止等待，提示登录过期，保留本地预览并引导重新登录 |
| 网络中断 | 显示网络错误和“重试”按钮；不得展示半成品结果 |
| 模型服务不可用 | 返回明确的服务错误；前端提示稍后重试，不输出默认分类 |
| 推理超时 | 建议前端等待上限 10 秒；超时后提示“分析超时，请重试”，不自动判为 NORMAL |
| Grad-CAM 生成失败 | 保留分类结果，热力图区域显示不可用，记录中标记 `gradcam_status=FAILED` |
| 返回概率和不等于 1 或超出 `[0,1]` | 视为数据异常，禁止展示和保存 |
| 未保存时刷新页面 | 提示结果将丢失；用户确认后清空当前结果 |
| 点击重新分析 | 若有未保存结果，先确认是否放弃，再清空文件与结果 |

## 4.6 M4 统计仪表盘

|---|---|
| 横轴 | 最近 7 个自然日，格式 `MM-DD`，按时间升序 |
| 纵轴 | 当日已保存记录数量，从 0 开始，刻度为整数 |
| 数据系列 | `NORMAL` 与 `PNEUMONIA` 两条折线，必要时可增加“总计” |
| 缺失日期 | 无记录日期必须补 0，不得跳过日期导致趋势失真 |
| 交互 | 悬浮显示日期、类别和数量；图例可切换系列显示 |
| 动画 | 首次加载时折线从左向右绘制，时长约 600 ms |
| 空状态 | 7 天内无任何记录时显示统一空状态，不展示虚假基线 |
| 时间口径 | 使用 `Asia/Shanghai` 自然日边界，不按浏览器所在时区重新切分 |

### 4.6.4 页面结构

1. 顶部 KPI 卡片：近 7 天总记录数、正常数、肺炎数、肺炎占比。
2. 左侧比例饼图卡片：阴阳性比例。
3. 右侧趋势折线图卡片：近 7 天分类趋势。
4. 数据说明区：注明“数据来源于当前账号已保存记录”。

### 4.6.5 边界条件

- 新账号无历史记录时，所有 KPI 显示 0，图表显示空状态而非报错。
- 某一天只有一种类别时，另一类别补 0。
- 统计接口失败时显示错误提示和重试按钮，不清零已有可信数据。
- 统计接口返回的 `normal + pneumonia` 必须等于 `total`；不一致时前端提示数据异常并等待刷新。
- 图表容器尺寸变化时应自动重绘，避免窗口缩放后模糊或溢出。
- 统计结果不作为疾病流行趋势或真实人群流行病学结论，页面不得作出公共卫生推断。

### 4.7.6 E1 骨干网络对比

E1 采用单变量实验，只改变骨干网络，其余训练协议保持一致。

| 骨干 | Test Acc | Test F1 | Test AUC | PNEUMONIA Recall | NORMAL Recall |
|---|---:|---:|---:|---:|---:|
| **ResNet50 Baseline** | **0.9743** | **0.9675** | **0.9946** | **0.9812** | 0.9557 |
| ResNet18 Baseline | 0.8868 | 0.8705 | 0.9751 | 0.8518 | 0.9810 |
| ResNet34 Baseline | 0.8645 | 0.8456 | 0.9680 | 0.8329 | 0.9494 |
| DenseNet121 Baseline | 0.8645 | 0.8452 | 0.9624 | 0.8353 | 0.9430 |
| EfficientNet-B0 Baseline | 0.8456 | 0.8292 | 0.9766 | 0.7929 | 0.9873 |

展示结论：

- ResNet50 的 Test F1 与 AUC 均排名第一。
- 小容量骨干和部分轻量骨干在该数据规模下未达到基线水平。
- EfficientNet-B0 的 AUC 较高但阈值敏感，说明概率排序能力与固定阈值下的分类表现不能混为一谈。

### 4.7.7 E2 注意力消融实验

E2 采用逐步单变量策略：朴素插入注意力、恒等初始化、注意力参数使用更低学习率，其他协议保持不变。

| 变体 | 最佳 Val F1 | Test Acc | Test F1 | Test AUC | PNEUMONIA Recall |
|---|---:|---:|---:|---:|---:|
| **Baseline（无注意力）** | **0.9826** | **0.9743** | **0.9675** | **0.9946** | **0.9812** |
| SE v1 | 0.9680 | 0.9708 | 0.9637 | 0.9901 | 0.9694 |
| CBAM v1 | 0.9721 | 0.9743 | 0.9678 | 0.9919 | 0.9765 |
| CBAM v2（恒等初始化） | 0.9615 | 0.9657 | 0.9574 | 0.9901 | 0.9647 |
| CBAM v3（恒等初始化 + 低学习率） | 0.9630 | 0.9708 | 0.9635 | 0.9906 | 0.9741 |

展示结论必须包括：

1. SE/CBAM 所有变体均未在综合指标上超过基线。
2. 医学场景最关注的 PNEUMONIA Recall 上，基线漏诊 8 例，少于所有注意力变体。
3. CBAM 初期存在空间门随机初始化导致的性能塌方，恒等初始化后明显修复。
4. 后续学习率震荡通过单独降低注意力参数学习率得到缓解，但仍未超过基线。
5. 最终结论：在本数据集与训练协议下，采用无注意力 `resnet50_baseline`，不为了名称强行叠加注意力模块。

### 4.7.8 E3 数据增强消融实验

| 增强变体 | Test Acc | Test F1 | Test AUC | PNEUMONIA Recall |
|---|---:|---:|---:|---:|
| **Baseline（全量增强）** | **0.9743** | **0.9675** | **0.9946** | **0.9812** |
| 无增强 | 0.9177 | 0.9017 | 0.9775 | 0.9059 |
| 仅几何增强 | 0.8491 | 0.8317 | 0.9653 | 0.8024 |
| 仅颜色增强 | 0.9160 | 0.9008 | 0.9774 | 0.8965 |
| 强增强 | 0.8319 | 0.8153 | 0.9562 | 0.7765 |
| 仅翻转 | 0.9177 | 0.9020 | 0.9779 | 0.9035 |

展示结论：

- 去掉全部增强后 Test F1 明显下降，全量增强对抑制过拟合有效。
- 任一单项增强子集均无法追平全量组合。
- 更强扰动没有带来收益，说明限制上限的关键因素是数据规模与数据分布，而非继续加强扰动。

## 5.3 影像预测：`/api/predict`

### 5.3.1 单张影像推理

| 项目 | 内容 |
|---|---|
| 方法 | `POST` |
| 路径 | `/api/predict` |
| 鉴权 | 需要 |
| Content-Type | `multipart/form-data` |
| 文件字段 | `file` |
| 限制 | 单文件，JPG/JPEG/PNG，`0 < size <= 10 MB` |

成功响应 `200 OK`：

```json
{
  "request_id": "req_20261115_001",
  "prediction_id": "pred_01JY8M2K7Q",
  "prediction": {
    "probs": {
      "NORMAL": 0.4212,
      "PNEUMONIA": 0.5788
    },
    "label": "PNEUMONIA",
    "threshold": 0.5101,
    "confidence": 0.5788
  },
  "gradcam": {
    "status": "READY",
    "original_url": "/api/files/original/pred_01JY8M2K7Q",
    "heatmap_url": "/api/files/heatmap/pred_01JY8M2K7Q",
    "overlay_url": "/api/files/overlay/pred_01JY8M2K7Q"
  },
  "model_version": "resnet50_baseline",
  "deployment_format": "ONNX_FP32",
  "inference_ms": 28,
  "created_at": "2026-11-15T14:30:00+08:00"
}
```

预测字段说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `prediction.probs` | 对象 | 是 | 两个类别概率，之和为 1，值域 `[0,1]` |
| `prediction.label` | 字符串 | 是 | `NORMAL` 或 `PNEUMONIA` |
| `prediction.threshold` | 数值 | 是 | 当前固定为 `0.5101`，前端必须展示后端返回值 |
| `prediction.confidence` | 数值 | 是 | 判定类别对应的概率，用于主置信度展示 |
| `gradcam.status` | 字符串 | 是 | `READY` 或 `FAILED` |
| `gradcam.overlay_url` | 字符串/空值 | 否 | 原图与热力图叠加地址；失败时可为空 |
| `model_version` | 字符串 | 是 | 在线模型版本，当前为 `resnet50_baseline` |
| `deployment_format` | 字符串 | 是 | 当前为 `ONNX_FP32` |
| `inference_ms` | 整数 | 否 | 后端模型及热力图处理耗时参考值 |
| `created_at` | 字符串 | 是 | 预测生成时间 |

接口行为要求：

- 服务端必须使用 `label = (probs.PNEUMONIA >= threshold ? PNEUMONIA : NORMAL)` 的统一规则。
- 当前版本必须调用 FP32 ONNX 模型，不根据前端参数切换模型。
- Grad-CAM 生成失败时，只要分类推理成功，仍返回 `200`，并设置 `gradcam.status=FAILED`。
- 该接口只生成临时预测结果，不自动写入历史记录。
- `prediction_id` 在保存前应具备唯一性和短期有效期，建议 24 小时内可保存。
- 不得将 `logits` 直接当作概率展示；如需返回，应明确标记为调试字段，默认不写入响应。

## 5.7 统一错误结构

```json
{
  "request_id": "req_20261115_004",
  "code": "FILE_TOO_LARGE",
  "message": "文件大小不得超过 10 MB",
  "details": {
    "max_mb": 10
  }
}
```

核心错误码：

| HTTP 状态 | 错误码 | 场景 |
|---:|---|---|
| 400 | `INVALID_REQUEST` | 请求字段缺失或格式错误 |
| 400 | `INVALID_FILE_TYPE` | 扩展名或 MIME 类型不受支持 |
| 400 | `INVALID_FILE_CONTENT` | 文件头与声明类型不一致或内容非法 |
| 401 | `UNAUTHORIZED` | 未携带 Token |
| 401 | `TOKEN_EXPIRED` | Token 已过期 |
| 401 | `INVALID_TOKEN` | Token 无效或被篡改 |
| 403 | `FORBIDDEN` | 无权限访问目标资源 |
| 404 | `RECORD_NOT_FOUND` | 历史记录不存在或无权访问 |
| 409 | `PREDICTION_EXPIRED` | 临时预测已过期，需重新分析 |
| 413 | `FILE_TOO_LARGE` | 文件超过 10 MB |
| 422 | `IMAGE_DECODE_ERROR` | 图片损坏、分辨率异常或无法解码 |
| 500 | `INTERNAL_ERROR` | 未预期的服务端错误 |
| 503 | `MODEL_UNAVAILABLE` | ONNX 模型或推理服务不可用 |
| 504 | `INFERENCE_TIMEOUT` | 推理或 Grad-CAM 生成超时 |

错误响应不得包含服务器堆栈、模型本地路径、JWT 内容或其他敏感信息。

# 6. 非功能性需求

## 6.1 性能要求

| 编号 | 指标 | 目标值 | 测量口径 |
|---|---|---|---|
| NFR-P-01 | 单张影像端到端响应 | P95 ≤ 3 秒 | 从点击“开始分析”到结果卡片可交互；包含 10 MB 以内文件上传、ONNX 推理和 Grad-CAM 生成 |
| NFR-P-02 | ONNX 预热推理耗时 | ≤ 500 ms | 后端单张、CPU、模型已预热；目标显著优于上限，实测参考约 28.3 ms |
| NFR-P-03 | Grad-CAM 生成耗时 | ≤ 1 秒 | 与推理同一请求内完成时的参考上限；超时应以前端可感知的方式降级 |
| NFR-P-04 | 普通页面首次加载 | ≤ 3 秒 | 本地或局域网、无冷启动依赖下载、Chrome/Edge 最新版 |
| NFR-P-05 | 页面交互响应 | ≤ 200 ms | 按钮反馈、筛选切换、弹窗打开等前端即时交互 |
| NFR-P-06 | 历史分页查询 | ≤ 1 秒 | 10,000 条记录以内、按当前用户和创建时间倒序 |
| NFR-P-07 | 并发演示能力 | 5 个并发预测请求不崩溃 | 课程演示环境；允许排队，但应返回明确状态，不得出现错图串结果 |
| NFR-P-08 | 错误恢复提示 | 5 秒内出现 | 模型不可用、网络中断或超时场景应及时反馈，不得无限转圈 |

性能验证条件：

- 端到端 3 秒指标以 100 Mbps 局域网、10 MB JPEG、服务端 CPU 4 线程、模型已完成预热为基准。
- 页面首次加载和模型冷启动可单独记录，但必须在 UI 上显示加载状态。
- 若文件上传本身耗时较长，应显示真实上传进度；进入推理后使用扫描动画，不伪造百分比。
- 性能指标不将用户思考时间、浏览器下载模型文件的时间和网络异常重试时间计入。

## 6.4 数据合规与隐私要求

- 系统仅使用公开、去标识化的课程实验数据，不接入真实医院患者数据。
- 业务页面不设置姓名、身份证号、住院号、联系方式等患者身份字段。
- 上传影像只用于本次辅助筛查、用户主动保存的记录和课程演示，不用于重新训练模型。
- 删除记录时同步删除关联原图和热力图，避免形成不可见残留副本。
- 演示环境中的数据结构、日志和导出图片均不得包含额外个人信息。
- 全站必须保留免责声明，且不得通过产品文案暗示系统具有临床诊断资质。
- 若未来接入真实医疗数据，必须重新进行隐私影响评估、权限设计和合规评审，不能沿用当前课程演示方案直接上线。

## 6.5 可靠性与可用性要求

| 编号 | 要求 |
|---|---|
| NFR-R-01 | 任何推理失败都不得返回默认 `NORMAL`、默认 `PNEUMONIA` 或伪造概率 |

| NFR-R-04 | 历史删除失败时保留原记录，不得先从前端删除造成假成功 |

## 6.6 可访问性与易用性要求

- 文字与背景对比度满足 WCAG 2.1 AA 的基础要求。
- 分类结果不得只靠红绿颜色表达，必须配文字、图标或形状差异。
- 所有按钮、上传区和弹窗支持键盘操作与清晰焦点态。
- 影像提供替代文本，说明是原始 X 光片还是 Grad-CAM 叠加图。
- 动画遵循 `prefers-reduced-motion`，用户可看到静态替代状态。
- 表单错误提示紧邻字段，并使用可被辅助技术识别的提示方式。
- 关键操作如删除、放弃未保存结果必须二次确认。
- 术语中文优先、英文类别保留，例如“正常（NORMAL）”“肺炎（PNEUMONIA）”。

## 6.7 可维护性与可观测性要求

- 模型版本、阈值、输入尺寸和类别顺序应由后端配置或模型元数据统一提供，避免前端多处硬编码。
- 每个请求生成 `request_id`，并在后端日志、错误响应和前端错误提示中可用于追踪。
- 记录预测耗时、Grad-CAM 状态、模型版本、HTTP 状态和错误码，但不记录敏感内容。
- 实验指标与模型信息看板应有快照版本，模型或报告更新时同步更新。
- 接口错误码和枚举值必须集中管理，前后端不得各自定义不一致的类别名称。
- 重要配置如 JWT 密钥、模型路径、数据库连接和允许来源应通过环境变量或配置文件注入。

| TC-UP-08 | 异常尺寸 | 上传极小或像素总量超限图片 | 拒绝并提示影像尺寸不符合要求 |
| TC-PRED-01 | 正常样例 | 上传已知 NORMAL 样例 | 返回合法 `probs`、`label`、`threshold`，结果页正常展示 |
| TC-PRED-02 | 肺炎样例 | 上传已知 PNEUMONIA 样例 | 徽章、概率、阈值和 Grad-CAM 均正确展示 |
| TC-PRED-03 | 阈值边界 | 构造 `probs.PNEUMONIA=0.5100` 与 `0.5101` 的测试响应 | `0.5100` 判 NORMAL，`0.5101` 判 PNEUMONIA |
| TC-PRED-04 | 概率非法 | 返回概率小于 0、大于 1 或和不为 1 | 前端显示数据异常，不允许保存 |
| TC-PRED-05 | 标签不一致 | 返回 `label` 与概率阈值计算结果冲突 | 前端拒绝展示为有效结果并提示异常 |
| TC-PRED-06 | Grad-CAM 失败 | 分类成功、热力图生成失败 | 显示分类结果和“热力图不可用”，不伪造热力图 |
| TC-PRED-07 | 模型不可用 | 停止 ONNX 服务后发起预测 | 返回 `503 MODEL_UNAVAILABLE`，页面提示重试 |
| TC-PRED-08 | 推理超时 | 模拟超过等待上限 | 返回超时状态，不自动判定为任一类 |
| TC-PRED-09 | 重复提交 | 分析中再次点击或网络重试 | 只产生一个有效预测请求或只保留一个结果 |
| TC-HIST-01 | 分页与筛选 | 切换 NORMAL/PNEUMONIA、页码和 page_size | 返回数据与筛选条件一致，页码状态正确 |
| TC-HIST-02 | 空历史 | 新账号进入历史页 | 展示空状态和前往工作台入口 |
| TC-HIST-03 | 越权查看 | 医生 A 访问医生 B 的记录 ID | 返回 404/403，不泄露记录内容 |
| TC-HIST-04 | 删除取消 | 点击删除后取消确认 | 不发起删除请求，记录保持 |
| TC-HIST-05 | 删除成功 | 确认删除记录 | 记录及关联文件删除，列表和统计刷新后同步减少 |
| TC-STAT-01 | 无数据统计 | 新账号打开统计页 | KPI 为 0，图表显示空状态，不报错 |
| TC-STAT-02 | 缺失日期补零 | 7 天内仅两天有记录 | 折线图仍展示连续 7 天，其余日期为 0 |
| TC-STAT-03 | 统计一致性 | 对比历史记录与统计结果 | 总数、分类数和趋势数量一致 |
| TC-UI-01 | 扫描动画 | 发起分析 | 图片上出现循环扫描线，结束后平滑切换结果 |
| TC-UI-02 | 数字滚动 | 结果出现 | 主置信度从 0 递增到接口值，最终值准确 |
| TC-UI-03 | 减少动态效果 | 开启 `prefers-reduced-motion` | 取消循环扫描和长动画，保留状态与结果 |
| TC-UI-04 | 页面切换 | 在工作台、历史、统计间切换 | 页面过渡平滑，无白屏和布局跳动 |
| TC-EXP-01 | 导出结果图片 | 点击导出 PNG | 图片包含结果、阈值、模型版本和完整免责声明，不含操作按钮 |
| TC-EXP-02 | 导出时资源失败 | 模拟热力图或字体加载失败 | 提示导出失败，不生成空白图片 |
| TC-COMP-01 | 浏览器兼容 | Chrome/Edge 最新版分别测试 | 主流程、图表和动画正常 |
| TC-COMP-02 | 分辨率兼容 | 1920×1080 与 1366×768 | 无关键内容遮挡，结果图可读 |

### 6.8.3 测试通过标准

1. 所有 P0 用例通过，且不存在阻塞主流程的缺陷。
2. 所有安全红线相关用例通过：未授权访问、越权访问、文件伪装、DICOM 拒绝、密码与 Token 泄露检查。
3. 预测结果字段 `probs`、`label`、`threshold` 在所有成功响应中存在且语义一致。
4. 阈值边界测试必须精确覆盖 `0.5100` 与 `0.5101`。
5. Grad-CAM 失败时，系统仍能正确降级，不产生虚假可视化。
6. Chrome/Edge 最新版、1920×1080 和 1366×768 的关键流程通过。

# 7. UI/UX 设计规范

## 7.1 整体视觉方向

系统采用深蓝医疗科技风，以“专业、克制、可信、可解释”为核心设计原则。视觉重点服务于影像、分类结果和 Grad-CAM，不使用与医疗场景无关的高饱和装饰和过度娱乐化动效。

| 设计要素 | 规范 |
|---|---|
| 主背景色 | `#0F172A` |
| 主强调色 | 极光青 `#06B6D4` |
| 次级强调色 | 蓝色 `#3B82F6` |
| 正常结果色 | `#22C55E` |
| 肺炎结果色 | `#EF4444` |
| 警告色 | `#F59E0B` |
| 主文字色 | `#E2E8F0` |
| 次文字色 | `#94A3B8` |
| 卡片背景 | 半透明深蓝，例如 `rgba(15, 23, 42, 0.72)` |
| 卡片描边 | `rgba(255, 255, 255, 0.12)` |
| 卡片圆角 | 18–24 px |
| 磨砂效果 | `backdrop-filter: blur(16px–20px)` 等效视觉要求 |
| 阴影 | 深色低透明度柔和阴影，避免厚重黑块 |
| 背景氛围 | 可用低透明度径向渐变模拟极光，或叠加极细网格纹理 |

### 7.1.1 Glassmorphism 卡片要求

- 卡片必须同时具备半透明背景、细边框、柔和阴影和背景模糊感。
- 磨砂玻璃效果不得降低文字和结果徽章的可读性。
- 卡片内部不使用复杂嵌套玻璃层，避免视觉噪点。
- Grad-CAM 影像区域可使用更深的背景和更清晰的边框，确保热力颜色不被玻璃效果污染。
- 不使用高亮大面积纯白卡片破坏深蓝色整体风格。

### 7.1.2 字体与排版

| 层级 | 建议规格 |
|---|---|
| 页面主标题 | 28–36 px，半粗体，字距略宽 |
| 卡片标题 | 18–22 px，中等字重 |
| 正文 | 14–16 px，行高 1.6–1.8 |
| 辅助说明 | 12–14 px，使用次文字色 |
| 分类徽章 | 16–20 px，粗体，保留 NORMAL/PNEUMONIA 英文 |
| 数字指标 | 使用等宽数字特性或专用数字字体，避免滚动时宽度跳动 |

中文使用系统可用的无衬线字体回退链，避免必须联网加载字体造成页面闪烁和导出缺字。

## 7.2 页面布局规范

- 桌面端建议采用左侧导航 + 顶部状态栏 + 主内容区布局；也可采用顶部导航，但必须保证主要功能在 1080p 下一屏可见。
- 主内容区最大宽度建议控制在 1440 px，居中排布，左右保留安全边距。
- 工作台上传卡片与结果卡片使用清晰的纵向流程，不使用过深的页面层级。
- 历史记录采用表格或紧凑卡片列表；统计页采用 KPI + 双图卡片布局。
- 模型信息看板采用锚点导航、指标网格和实验表格组合，避免成为一张超长无结构文档。
- 所有主要页面保持统一的页边距、卡片间距和标题层级。

## 7.3 动效要求

动效是该系统的明确验收项，目标是增强“AI 正在分析”的可感知性、结果呈现的仪式感和页面切换的连贯性，而不是为了炫技。

### 7.3.1 必须实现的动效

| 动效编号 | 名称 | 要求 |
|---|---|---|
| ANI-01 | X 光扫描线动画 | 分析期间在影像上显示循环扫描线，P0 必须实现 |
| ANI-02 | 置信度数字滚动 | 结果出现时主置信度从 0 递增至真实值，P0 必须实现 |
| ANI-03 | 页面切换过渡 | 业务页面切换使用淡入和轻微位移动效，P1 必须实现 |
| ANI-04 | 结果卡片入场 | 扫描结束到结果呈现使用 250–350 ms 淡入上移 |
| ANI-05 | ECharts 入场 | 饼图和折线图首次加载使用适度动画，时长约 600 ms |
| ANI-06 | 卡片悬浮反馈 | 可交互卡片悬浮时轻微提亮或上移 2–4 px |
| ANI-07 | 弹窗过渡 | 历史详情弹窗使用遮罩淡入和卡片缩放淡入 |

### 7.3.2 扫描线动画细节

- 位置：覆盖在原图或预览图上的独立遮罩层，不改变影像宽高比。
- 颜色：以 `#06B6D4` 为主，可叠加一层淡青色发光拖尾。
- 速度：单次从上到下约 1.8 秒，循环播放；结果到达后停止并淡出。
- 遮罩：使用深蓝色半透明遮罩，避免扫描线在肺部高亮区域不可见。
- 辅助文案：显示当前阶段，如“预处理”“模型推理”“生成热力图”。
- 进度：不得伪造百分比；若后端能返回真实阶段，可按阶段高亮，否则使用不确定进度。
- 性能：动画只使用 transform 和 opacity，避免持续触发布局重排。
- 无障碍：减少动态效果模式下显示静态扫描框和文案，不循环播放。

### 7.3.3 数字滚动动画细节

- 主置信度、肺炎概率可使用数字递增效果；判定阈值保持静态显示，避免误解阈值也在变化。
- 动画时长建议 800–1000 ms，使用先快后慢的缓动，最终精确停在接口值。
- 页面重复渲染时不得反复触发数字动画；每个结果只播放一次。
- 数字变化期间不得改变布局宽度，预留固定数字宽度或使用等宽数字。
- 用户启用减少动态效果时，直接展示最终数值。
- 动画结束前即可显示结果徽章，但标签和颜色不得闪烁变化。

### 7.3.4 页面切换与反馈

- 路由切换使用 250–300 ms 淡入 + 8 px 内位移，不阻塞页面操作。
- 页面切换不得出现明显白屏、长时间黑屏或布局跳变。
- 按钮悬浮和按下提供轻微颜色、亮度或位移反馈，时长 150–200 ms。
- Toast 提示从右上或顶部进入，展示 2.5–4 秒，错误提示不得自动过快消失。
- 加载状态优先使用骨架屏；涉及 AI 推理时使用扫描线动画，而非普通旋转加载图标。

## 7.4 关键页面视觉要求

### 7.4.1 登录页

- 深蓝背景 + 极光青色光晕，不堆叠过多医学影像装饰。
- 登录卡片采用磨砂玻璃质感，表单垂直居中。
- 页面标题清晰展示系统名称和“AI 辅助筛查参考工具”定位。
- 页面底部展示完整免责声明和“课程演示系统”标识。
- 不展示注册、忘记密码、第三方登录等未实现入口。

### 7.4.2 诊断工作台

- 首屏突出上传区，状态文案明确“支持 JPG/PNG，单张不超过 10 MB”。
- 结果出来后，分类徽章、置信度和阈值位于结果卡上部，原图与 Grad-CAM 位于下方。
- 结果区背景可加入极低透明度网格，突出医疗影像工作台氛围。
- PNEUMONIA 使用红色高风险提示，NORMAL 使用绿色，但均必须同时显示文字与图标。
- 免责声明使用独立底板或边框区域，不能淹没在正文中。
- 保存按钮为主操作，重新分析为次操作，导出为第三级操作。

### 7.4.3 历史记录页

- 顶部筛选条采用紧凑卡片布局，结果筛选使用分段控件或下拉框。
- 列表行突出缩略图、结果徽章、肺炎概率和时间。
- 删除按钮使用低饱和危险色，避免与查看详情争抢视觉焦点。
- 详情弹窗宽度适配 1080p，影像对比区保持清晰可读。

### 7.4.4 统计仪表盘

- KPI 卡片使用大号数字和简短标签，避免过多文字。
- 饼图与折线图放在同一视觉层级，颜色与结果徽章一致。
- 图表背景透明或使用深色卡底，网格线使用低透明度蓝色。
- 页面明确显示统计时间范围和“仅统计已保存记录”。

### 7.4.5 模型信息看板

- 首屏展示在线模型名称、最终选型和四个核心指标。
- 实验对比表使用重点行高亮，基线行和最终选型行视觉突出。
- E2 注意力消融应作为独立章节，使用“负结果与诊断链”标题，不让负结果看起来像失败页面。
- E1/E2/E3/E7 区块可使用标签页或锚点导航组织。
- Grad-CAM 样例区使用与原图对比的并排布局，并显示解释边界。
- 所有指标必须标注测试集口径或实验环境，不能只展示一个大数字。

## 7.5 状态与反馈规范

| 状态 | 视觉与交互要求 |
|---|---|
| 加载中 | 骨架屏或扫描动画；按钮显示处理中，不允许无反馈等待 |
| 成功 | 使用青绿色或正常绿色反馈；Toast 简洁说明结果 |
| 错误 | 使用红色错误提示，说明原因并提供重试；不展示内部错误堆栈 |
| 空状态 | 使用图标 + 一句说明 + 明确下一步按钮 |
| 禁用 | 降低透明度并禁用交互，但仍保持可读 |
| 危险操作 | 使用二次确认弹窗，默认焦点不在确认删除上 |
| 未保存离开 | 提示“当前结果尚未保存”，允许继续离开或取消 |
| 网络异常 | 保留当前内容，提供重试；不得清空已选影像 |

## 7.6 文案规范

- 统一使用“AI 辅助筛查结果”，不使用“确诊结果”“自动诊断结论”。
- 统一使用“肺炎概率”“正常置信度”“判定阈值”，不使用无法解释的“AI 分数”。
- 对 NORMAL 和 PNEUMONIA 同时给出中文解释：正常（NORMAL）、肺炎（PNEUMONIA）。
- 统一使用“模型关注区域”描述 Grad-CAM，不使用“病灶区域”“感染范围”等确定性表述。
- 错误文案说明用户下一步能做什么，例如“请更换图片”“请稍后重试”“请重新登录”。
- 不使用“绝对准确”“零误诊”“替代医生”等夸大表述。
- 页面中的模型信息、阈值与实验结论必须来自统一事实源，避免不同页面口径不一致。

## 7.7 可访问性与动效降级

- 所有动效均不得成为完成业务操作的前提。
- 分类结果通过颜色、图标和文字三重区分。
- 键盘用户可完成登录、上传、分析、保存和查看历史等核心流程。
- 扫描线、数字递增和页面过渡在 `prefers-reduced-motion` 下使用静态或即时呈现。
- 图表提供文字摘要和表格替代数据，避免只能通过视觉理解。
- 图像上传区在拖拽之外必须提供可点击选择入口。

# 8. 验收标准与交付优先级

## 8.1 P0 验收清单

| 验收项 | 通过条件 |
|---|---|
| 登录与鉴权 | 预置账号可登录；未登录无法访问业务页；无效或过期 Token 被拦截 |
| 上传限制 | 单张 JPG/PNG；10 MB 边界正确；伪装图片、DICOM、损坏图片被拒绝 |
| 推理与结果 | 使用 FP32 ONNX 与固定阈值 0.5101；返回并展示 `probs`、`label`、`threshold` |
| 扫描动画 | 分析过程中出现 CSS X 光扫描线，结束后平滑进入结果 |
| 结果展示 | 分类徽章红/绿区分且带文字；置信度数字滚动；原图与 Grad-CAM 左右对比 |
| 免责声明 | 登录页、结果卡片、历史详情和导出图片中可见 |
| 保存流程 | 结果可保存；重复保存不产生重复记录；保存失败可重试 |
| 历史记录 | 分页、结果筛选、详情弹窗可用；只显示本人记录 |
| 接口约定 | 预测响应包含合法概率、标签和阈值；错误响应结构统一 |
| 安全红线 | 密码不明文传输；文件双重校验；无 Token 请求返回 401 |
| 兼容性 | Chrome/Edge 最新版、1920×1080 下主流程可用 |

## 8.2 P1 验收清单

- 历史记录支持删除及二次确认。
- 统计仪表盘可展示阴阳性比例饼图和连续 7 天趋势。
- 模型信息看板完整展示 ResNet50 指标、E1/E2/E3/E7 实验结论和 Grad-CAM 样例。
- 页面切换、图表和弹窗动效完整。
- 1366×768 下核心内容无遮挡。
- 登录失败次数限制、统计数据刷新等增强能力可用。

## 8.3 P2 验收清单

- 结果卡片可通过 html2canvas 导出 PNG。
- 导出图片包含完整结果、阈值、模型版本和免责声明。
- 资源加载失败时给出明确提示，不产生空白或错误图片。

## 8.4 完成定义

一个功能只有同时满足以下条件，才视为完成：

1. 页面、接口和错误状态均已实现；
2. 输入校验和边界条件符合本文档；
3. 与真实 ONNX 推理结果联调通过，不使用假数据冒充最终结果；
4. 通过对应 P0 测试用例；
5. 免责声明、模型版本和阈值展示正确；
6. 无敏感信息出现在页面、URL 或日志中；
7. 相关接口和交互已写入测试记录或联调说明。

## 9.1 当前默认决策

| 事项 | 默认决策 |

| 账号来源 | 部署时预置演示账号，密码以哈希保存 |
| JWT 有效期 | 2 小时，无刷新 Token；过期后重新登录 |
| 记录归属 | 历史记录和统计只针对当前登录医生 |
| 记录保存时机 | 用户点击“保存记录”后写入，不在预测时自动保存 |
| 临时预测有效期 | 建议 24 小时，过期后需重新分析 |
| Grad-CAM 处理 | 与分类同步返回；失败时保留分类结果并标记不可用 |
| 统计时间范围 | 固定最近 7 个自然日，使用 `Asia/Shanghai` |
| 模型阈值来源 | 后端或模型元数据返回，前端展示接口值 |
| 结果导出 | P2 可选，采用 html2canvas |
| 批量上传 | 不支持 |
| DICOM | 不支持，直接拒绝 |

## 9.2 需要在详细设计中进一步确认的事项

1. 预置演示账号的具体创建方式和密码交付方式，仅允许在部署说明中受控记录。
2. 临时预测文件和热力图的具体保留时长与清理机制。
3. 历史记录和统计数据的持久化选型，以及删除后的文件清理策略。
4. Grad-CAM 与分类是否严格同步完成；若后续改为异步生成，需要新增状态轮询接口或事件机制。
5. 是否需要增加日期范围筛选；当前 P0 只要求结果筛选和分页。
6. 模型信息看板采用后端接口动态加载还是前端打包静态快照；无论采用哪种方式，都必须显示快照版本并保留离线降级能力。
7. 报告导出中的影像清晰度、文件体积和浏览器兼容性验收细则。
