## 一、项目背景与意义

肺炎是全球范围内发病率和死亡率较高的呼吸系统疾病，胸部 X 光片（Chest X-ray, CXR）是临床筛查肺炎最常用、最经济的影像手段。然而：

- 基层医疗机构放射科医师不足，阅片工作量大、易疲劳；
- 不同医师之间诊断一致性有限，存在漏诊、误诊风险；
- 人工阅片效率低，难以满足大规模筛查需求。

本项目基于**深度学习卷积神经网络（CNN）**，构建一套**肺炎 X 光片智能辅助诊断系统**，实现"上传影像 → 自动判别正常/肺炎 → 输出置信度与可视化依据"的完整流程，为临床辅助筛查提供参考。

**应用价值**：辅助基层医生快速初筛、缓解阅片压力；通过 **Grad-CAM 热力图**给出模型决策依据，提升 AI 的可解释性与医生信任度。

**与课程结合**：核心采用课程重点章节（第 2 章 卷积神经网络，6 学时）技术，并涉及迁移学习、注意力机制、模型部署优化等进阶内容。

## 三、数据集

| 项 | 内容 |
|---|---|
| 名称 | Chest X-Ray Images (Pneumonia) |
| 来源 | Kermany et al., *Cell*, 2018（公开去标识化数据集，合规） |
| 地址 | https://www.kaggle.com/datasets/paultimothymooney/chest-xray-pneumonia |
| 规模 | 约 5863 张，2 类（NORMAL / PNEUMONIA） |
| 许可 | 公开科研用途 |
| 升级数据 | COVID-19 Radiography Database（https://www.kaggle.com/datasets/tawsifurrahman/covid19-radiography-database） |

> **⚠️ 重要注意（已知坑）**：该数据集官方 `val/` 仅 16 张、`test/` 约 624 张，划分不合理。本项目**不使用官方 val**，将原始数据合并后按 **8 : 1 : 1** 重新分层划分，保证实验严谨性。

### 3.1 数据采集与合规
- 使用公开、已去标识化的医学影像数据集，**不涉及患者隐私**；
- 在报告与文档中**明确标注数据来源、许可与引用**。

### 3.2 数据标注与预处理
1. **清洗**：剔除损坏、重复、异常尺寸图像。
2. **类别平衡分析**：统计各类样本数，必要时使用类别权重 / 重采样。
3. **预处理**：统一尺寸（如 224×224）、灰度转三通道（适配预训练骨干）、归一化（ImageNet 均值方差）。
4. **数据增强**：随机水平翻转、随机旋转、随机裁剪、色彩抖动（仅用于训练集）。
5. **数据集划分**：8:1:1 分层划分，随机种子固定，保证可复现。

## 四、技术方案与系统架构

### 4.1 总体架构（前后端分离）

```
┌──────────────────────────────────────────────────────────┐
│  前端 Vue3 + Element Plus + ECharts                        │
│  功能：登录 / 上传X光片 / 结果与热力图展示 / 历史记录 / 统计图 │
└───────────────▲──────────────────────────────────────────┘
                │  HTTP REST (JSON / multipart)
┌───────────────┴──────────────────────────────────────────┐
│  后端 FastAPI + Uvicorn                                    │
│  功能：JWT鉴权 / 业务逻辑 / 历史记录(SQLAlchemy→DB)         │
│        调用推理模块 / 组织返回结果                          │
└───────────────▲──────────────────────────────────────────┘
                │  进程内调用（核心版）或 微服务调用（进阶版）
┌───────────────┴──────────────────────────────────────────┐
│  AI 推理模块：PyTorch / ONNX Runtime                       │
│  功能：分类推理 + 置信度 + Grad-CAM 热力图生成              │
└──────────────────────────────────────────────────────────┘
```

### 4.2 技术栈

| 层次 | 技术选型 |
|---|---|
| 前端 | Vue 3 (Composition API) + Vite + Element Plus + Axios + Vue Router + Pinia + ECharts |
| 后端 | FastAPI + Uvicorn + Pydantic + SQLAlchemy + JWT + SQLite(开发)/MySQL(可选) |
| AI | PyTorch + torchvision/timm + pytorch-grad-cam + ONNX Runtime |
| 部署 | 本地一键启动；可选 Docker 打包 |

**选型理由**：后端与 AI 同为 Python，模型调用零成本；FastAPI 自带交互式 API 文档（`/docs`），便于答辩演示；前端 Vue3 生态成熟、开发快、组件丰富。

### 4.3 系统功能模块

1. **用户模块**：注册/登录（JWT 鉴权）。
2. **影像上传模块**：上传 X 光片、格式/大小校验、预览。
3. **AI 诊断模块**：调用模型推理，返回类别、置信度、Grad-CAM 热力图。
4. **结果展示模块**：原图/热力图对比、诊断结论、置信度。
5. **历史记录模块**：查询、查看、删除历史诊断。
6. **统计模块（可选）**：历史诊断统计图表（ECharts）。

> 说明：本系统定位为**辅助诊断参考**，不替代医生诊断，界面需有相应免责声明。

## 五、AI 模型设计与实验方案

### 5.1 模型主线
- **基线**：ResNet50（ImageNet 预训练，迁移学习）。
- **对比骨干**：VGG16 / MobileNetV3 / EfficientNet-B0。
- **创新点**：在 ResNet50 中引入 **注意力模块（SE 或 CBAM）**，增强对病灶区域的特征响应。

### 5.2 训练策略
- 迁移学习：冻结骨干 → 微调全网络（分阶段）；
- 损失函数：交叉熵（可选类别权重处理不平衡）；
- 优化器：Adam / SGD + 动量；
- 学习率：余弦退火 / StepLR 调度；
- 正则与早停：Dropout + Early Stopping；
- 评价指标：Accuracy、Precision、Recall、F1、AUC、混淆矩阵。

### 5.3 实验设计（对应评分"AI工作量 + 效果"）

| 实验 | 目的 | 产出 |
|---|---|---|
| E1 骨干对比 | 选最优骨干 | 各模型 指标/参数量/推理时间 对比表 |
| E2 注意力消融 | 证明创新点有效 | ResNet50 vs +SE vs +CBAM 消融表 |
| E3 数据增强消融 | 证明增强有效 | 有无增强对比 |
| E4 超参调优 | 找最优配置 | 学习率/batch/尺寸 网格搜索结果 |
| E5 交叉验证 | 评估稳定性 | 5 折交叉验证均值±方差 |
| E6 可解释性 | 决策依据可视 | Grad-CAM 热力图 |
| E7 部署优化 | 精度 vs 速度 | PyTorch vs ONNX vs 量化 对比表 |

> 上述实验构成"模型选择合理 → 设计有创新 → 算法优化充分 → 实验严谨"的完整证据链，是冲击高分的核心。

### 5.4 模型部署
- 训练完成后导出为 **ONNX**，使用 **ONNX Runtime** 推理；
- 对比**动态量化前后**的精度损失与推理速度提升；
- 集成到 FastAPI 后端，实现在线推理。
